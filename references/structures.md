# 结构套路参考（structures）

> 用途：识别与改写 AI 文本的**结构指纹**。结构比词语更难在改写时消除（位置指纹：段落等长、引语总在段尾、列举总是三项、过渡总是同一公式、强调均匀分布）。每条列出识别特征、中英示例、改法与保留边界。编号对应统一模式分类法。

## 元信息

| 项 | 内容 |
|---|---|
| 语言 | 中文优先，中英双语 |
| 覆盖分类 | A1–A5、B6–B11、C13、E22、F30–F31，以及 stop-slop 结构与 de-AI 篇章层检查 |
| 使用原则 | 单个套路偶尔出现不算问题，成簇、连段、每段一次才修；先判断信息是否重复/空泛，再改结构 |

## 结构套路清单

### 1. 二分对照壳（不是 X 而是 Y）——A1

| 要素 | 内容 |
|---|---|
| 识别特征 | 「不是 X 而是 Y」「不在于 X 而在于 Y」「这不只是 X，更是 Y」；否定半句是无中生有，只抬高语气 |
| 例子（中） | 「这不仅是一个导出按钮，更是通往高效工作的全新入口。」 |
| 例子（英） | "It's not just a song; it's a statement." |
| 改法 | 直接陈述 Y；否定半句纠正真实误解时才保留 |
| 何时保留 | 否定部分纠正读者确实持有的误解（「错误发生在保存阶段，而不是上传阶段」）；两部分都承载信息 |

### 2. 先扬后抑（拔高后转折）——C13

| 要素 | 内容 |
|---|---|
| 识别特征 | 先铺陈「意义/成就/前景」，再「然而/但是」转向问题；转折前的拔高无独立信息 |
| 例子（中） | 「尽管面临诸多挑战，凭借战略布局，该地区依然蓬勃发展。」 |
| 例子（英） | "Despite these challenges, Korattur continues to thrive." |
| 改法 | 保留事实，删掉拔高；直接写「该地区有交通拥堵和缺水问题」 |
| 何时保留 | 转折前的信息本身有依据（真实成就/数据）；作者明确表达的两面评价 |

### 3. 三段递进 + 升华收尾——B6、C13

| 要素 | 内容 |
|---|---|
| 识别特征 | 三个并列事实后接一句抽象升华（「这告诉我们……」「意义深远」）；三项常是凑数 |
| 例子（中） | 「功能新增了导出、搜索、批量重命名，标志着效率的全新飞跃。」 |
| 例子（英） | "The event offers talks, panels, and networking — a testament to innovation." |
| 改法 | 检查三项是否各自独立；只留真信息，删升华句；不足三项就合并 |
| 何时保留 | 三项确实是三个不同功能/事实（「导出、搜索、批量重命名是三个功能」）；刻意排比且每项有信息 |

### 4. 自问自答开场——A4

| 要素 | 内容 |
|---|---|
| 识别特征 | 「为什么要关心 X？因为……」「X 值得做吗？答案是肯定的」；问题只是起跑式铺垫 |
| 例子（中） | 「为什么效率如此重要？因为它决定了产出。」 |
| 例子（英） | "Why does caching matter? Because it cuts repeat work." |
| 改法 | 删掉问题，直接陈述答案；真能引导读者思考的设问可留 |
| 何时保留 | 问题承载真实疑问（如归谬「你可能会想……」）；对话文体中有意互动 |

### 5. 列举型（首先/其次/最后）——F30、B7

| 要素 | 内容 |
|---|---|
| 识别特征 | 每段/每句以「首先/其次/最后」「第一/第二/第三」开头；路标掩盖了信息进入方式雷同 |
| 例子（中） | 「首先，提升效率。其次，降低成本。最后，增强体验。」 |
| 例子（英） | "First, speed. Second, cost. Third, experience." |
| 改法 | 有真实顺序就保留路标，无顺序就按内容自然衔接；不强行合并连贯段落 |
| 何时保留 | 步骤/流程有真实先后（「首先安装，其次配置」）；千字文中一两个路标词正常 |

### 6. 故事开场（套模板叙事）——stop-slop narrative template

| 要素 | 内容 |
|---|---|
| 识别特征 | 「记得有一天……」「曾经……」；模板化的「当时我 X，现在我 Y」弧线 |
| 例子（中） | 「记得刚入职时，我还是个职场小白。如今，我已独当一面。」 |
| 例子（英） | "By the time I reached the office, I was already exhausted." |
| 改法 | 删掉套话外壳，直接讲具体事件；保留真实的时间关系 |
| 何时保留 | 故事是真实经历且有细节（真实时间、地点、人物）；虚构创作任务 |

### 7. 数据堆砌无解释——C12 邻近

| 要素 | 内容 |
|---|---|
| 识别特征 | 连排数字/指标，不给背景、比较或结论；数字成为装饰 |
| 例子（中） | 「产品用户突破 1000 万，营收增长 200%，市场覆盖 30 个城市。」 |
| 例子（英） | "Over 10 million users, 200% growth, 30 cities." |
| 改法 | 删冗余数字，或给关键数字加一句比较/含义；不编造缺失的数字 |
| 何时保留 | 数字有明确来源且服务于论点（时间序列、对比基线）；数据表/附录 |

### 8. 每段连接词开头——B7、de-AI 路标词

| 要素 | 内容 |
|---|---|
| 识别特征 | 每段以「更重要的是/换句话说/事实上/与此同时」开头；抽首句连读是一份完整摘要（提纲扩写形状） |
| 例子（中） | 「与此同时，成本在下降。更关键的是，质量在提升。」 |
| 例子（英） | "Moreover, costs fell. Crucially, quality rose." |
| 改法 | 改变信息进入段落的方式（用具体事实开头），不是机械换路标词 |
| 何时保留 | 路标词表达真实关系（同时、转折、递进）；千字文一两个正常 |

### 9. 先道歉/客套后转折——E22

| 要素 | 内容 |
|---|---|
| 识别特征 | 「对不起，我可能说得不够清楚，但是……」；道歉/客套包裹着本可直接说的内容 |
| 例子（中） | 「不好意思，可能有点绕，但核心意思是这个。」 |
| 例子（英） | "Sorry if this is confusing, but the point is simple." |
| 改法 | 删客套，直接说核心；对话中真实致歉可留 |
| 何时保留 | 真实对话场景、邮件致歉；确实需要表达歉意时 |

### 10. 总结升华结尾——F31、C13

| 要素 | 内容 |
|---|---|
| 识别特征 | 结尾段抽象概括全文 + 展望（「总而言之……未来可期」）；每段都补一句结论 |
| 例子（中） | 「总而言之，这次升级意义重大，未来前景光明。」 |
| 例子（英） | "In conclusion, this marks a pivotal moment with exciting times ahead." |
| 改法 | 停在最后一个具体事实上；有真实计划就写计划 |
| 何时保留 | 有实质内容的总结（「综上，两种方案都不满足要求」）；真实行动计划 |

### 11. 负面清单式展开——A1、stop-slop negative listing

| 要素 | 内容 |
|---|---|
| 识别特征 | 「不是 A，不是 B，是 C」；通过一连串否定制造悬念，读者不需要这段跑道 |
| 例子（中） | 「它不是工具，不是平台，而是一种全新的协作方式。」 |
| 例子（英） | "Not a fix. Not a workaround. A philosophy." |
| 改法 | 直接陈述 C；真实对照/否定可保留 |
| 何时保留 | 否定项是读者确实会混淆的真实选项；引语 |

### 12. 假主体 / 无施事者——B11、stop-slop false agency

| 要素 | 内容 |
|---|---|
| 识别特征 | 「数据告诉我们」「文化发生了转变」「决定自然浮现」；非生命体充当动作主体，回避了做事的人 |
| 例子（中） | 「数据表明，用户更偏好简洁界面。」 |
| 例子（英） | "The data tells us users prefer simple interfaces." |
| 改法 | 点名施事者（「团队分析数据后发现……」）；施事者未知就保留被动 |
| 何时保留 | 施事者确实未知或不重要（「样本已被污染」）；统计表述本身（「数据显示」作为日常说法） |

### 13. 段落同构（观点 + 解释 + 段尾总结）——de-AI 篇章层

| 要素 | 内容 |
|---|---|
| 识别特征 | 连续 3 段都是「观点句 + 解释 + 段尾抽象结论」；每段结尾都补一句概括 |
| 例子（中） | 「①协作很重要。团队一起工作更高效。这凸显了协作的价值。/ ②安全很关键……」 |
| 例子（英） | "①Speed matters. Fast sites retain users. This shows speed's value. / ②Reliability matters too..." |
| 改法 | 改变信息进入方式，段尾停在实际结果/场景/引语上；不把连贯文章拆成要点 |
| 何时保留 | 观点、解释、结论各自有独立信息；正式报告/公文的结构要求 |
